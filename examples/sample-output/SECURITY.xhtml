Security Policy

Acme Inc takes the security of our software and services seriously. If you believe you have found a security vulnerability, we encourage you to report it responsibly.

Reporting a Vulnerability

Please do NOT report security vulnerabilities through public GitHub issues.

Instead, please report them via email:

  • Email: legal@acme.com

Please include the following information in your report:

  • Description of the vulnerability

  • Steps to reproduce the issue

  • Potential impact of the vulnerability

  • Any suggested fixes (optional)

Scope

In Scope

  • Acme Inc application code and APIs

  • Authentication and session management

  • Data storage and transmission

  • Infrastructure serving https://acme-saas.com

Out of Scope

  • Third-party services and applications

  • Social engineering attacks

  • Denial of service (DoS/DDoS) attacks

  • Issues in dependencies that are already publicly disclosed

Authentication Security

This project uses authentication services. Security issues related to the following are especially important to us:

  • Session management and token handling

  • Authentication bypass vulnerabilities

  • Credential storage and transmission

  • OAuth flow and callback security

Payment & PCI Considerations

This project integrates with payment processing services. We follow PCI DSS guidelines for handling payment data:

  • Payment card data is never stored on our servers; it is handled by our PCI-compliant payment processor

  • Vulnerabilities related to payment flows, billing data exposure, or payment bypass are treated as critical

  • If you discover a payment-related vulnerability, please include [PCI] in your report subject line

AI Safety & Security

This project integrates with AI/ML services. In addition to traditional security concerns, we are interested in reports related to:

  • Prompt injection vulnerabilities

  • Data leakage through AI model interactions

  • Unauthorized access to AI-generated content

  • Model manipulation or adversarial inputs

  • AI output used to bypass security controls

Disclosure Policy

We follow a coordinated disclosure process. We ask that you:

  • Allow us reasonable time to investigate and address the vulnerability before public disclosure

  • Make a good faith effort to avoid privacy violations, data destruction, and service disruption

  • Do not access or modify data belonging to other users
